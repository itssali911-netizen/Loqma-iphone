# إصلاح تقييم اللياقة — 2.8

## السبب والتغيير

- لم يكن الطول معطوبًا بسبب الخط: الشرطة كانت حقلًا فارغًا. السحب والأزرار كانت تشترط قيمة موجودة مسبقًا.
- أُزيل سحب العمر الرأسي الذي كان يتنافس مع تمرير الصفحة. استُخدم Slider أفقي أصلي وحقل رقمي واضح وزرا زيادة ونقصان. جميعها تعدّل نفس الربط. نقطة بداية المؤشر ليست إجابة محفوظة؛ يجب الاختيار قبل متابعة الحقول المطلوبة.
- النص الخام محفوظ في المسودة. الإدخال الخاطئ لا يُمحى عند إغلاق لوحة المفاتيح ولا يتحول إلى قيمة محدودة صامتًا. الأخطاء تمنع المتابعة حتى التصحيح؛ يمكن حفظ المسودة غير المكتملة.
- لم تعد واجهات الأرقام تملك حالة نص منفصلة تعاد تهيئتها عند تغيير الصفحة. القيمة والوحدة ظاهرتان بعد الاختيار، والأرقام غربية مع واجهة عربية RTL.

## الأسئلة: 11 خطوة بدل 17

الهدف، الملاءمة، الجنس للمعادلة، العمر، الطول، الوزن، وزن الهدف والوتيرة (اختياري)، النشاط والخطوات الاختيارية، التدريب (اختياري)، التفاصيل (اختياري)، المراجعة.

- جُمعت صفحة وزن الهدف وصفحة الوتيرة. جُمعت الخبرة وأيام التدريب ومدته، وأُزيل تكرار إدخال أيام التدريب بالحقل وبالشبكة.
- أُزيلت الأسئلة المستقلة عن مكان التدريب والأنشطة المفضلة وجودة النوم ومواعيده والإجهاد؛ هذه القيم لا تؤثر في الحساب الحالي. بقيت الحقول القديمة قابلة للقراءة ومحفوظة ومعروضة ضمن التفاصيل السابقة/الملف.
- بقيت ساعات النوم الاختيارية لأنها تؤثر في اقتراح الراحة. صارت تفضيلات الغذاء وعدد الوجبات والملاحظات ضمن قسم مطوي اختياري، مع توضيح أنها للمراجعة ولا تصفّي الوصفات تلقائيًا.
- أُعيدت صياغة مستويات النشاط بأمثلة يومية، واستُبدلت عبارة «إعادة تركيب الجسم» بوصف خفض الدهون مع بناء العضلات، ووُضّح معنى تعديل السعرات التدريجي والمعتدل.
- سؤال الملاءمة يأتي مبكرًا، ويشرح مباشرة لماذا لا ينشئ التقدير خطة للحالات غير المدعومة.
- التخطي لا يمسح إجابة موجودة. الفهارس القديمة تُرحّل إلى معرفات شاشات ثابتة دون إعادة ضبط المسودة أو تغيير معادلات الخطة المحفوظة.

## الاستجابة والحفظ

- لا حفظ على القرص أثناء تحريك المؤشر؛ لا إعادة حساب للخطة أثناء السحب. تتجاهل الأداة أحداث المؤشر التي لم تغيّر الرقم.
- التحقق من السجل وترميزه للحفظ ومعاينة الخطة يعملان خارج MainActor؛ استبدال الملف الذري يبقى متسلسلًا لحماية البيانات.
- عند تغيير السجل أثناء الترميز، يعاد البناء من أحدث سجل. طلبات اللياقة الأحدث تلغي كتابة طلب قديم، بما في ذلك الحذف والاستيراد، حتى لا تعود مسودة محذوفة.
- «حفظ وإكمال لاحقًا» عملية واحدة بدل كتابة المسودة ثم تأجيل التقييم ثم إعادة الكتابة عند اختفاء الشاشة.
- بوابة قصيرة للأزرار تمنع تكرار الانتقال بسبب الضغط المزدوج؛ لا تحريك ثقيل للصفحة كاملة.

## التحقق

أُضيفت اختبارات Core للترحيل والحفظ والمدخلات والحدود؛ وُسّع اختبار iOS الحقيقي لبدء العمر والطول من الفراغ، والسحب المتكرر، والإدخال اليدوي، والقيم غير الصالحة، والرجوع، وإغلاق التطبيق واستكمال المسودة، والتخطي، والضغط المزدوج، ثم المعاينة والاعتماد والحذف مع حماية الطعام والأهداف.

تُحفظ نتائج البناء وتشغيل هذه الاختبارات في GitHub Actions. إعداد الاختبارات لا يُعد اجتيازًا لها؛ يُذكر رقم التشغيل ونتيجته في تقرير التسليم بعد تنفيذه.

على Windows نجحت 55 حالة Python مع تخطي حالتين خاصتين بالنظام؛ فشلا صلاحيات POSIX في المجموعة الكاملة مرتبطان بـWindows، ولم تُضعف اختبارات التوقيع لتجاوزهما. يجب أن تعمل المجموعة كاملة على macOS في البناء. لم تُقس معدلات الإطارات أو استهلاك الذاكرة على هاتف فعلي متوسط الأداء، ولا تُدّعى سلاسة كمية قبل ذلك.
