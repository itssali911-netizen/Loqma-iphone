# كتالوج Open Food Facts الخادمي للُقمة

## الحالة الفعلية — 2026-11-03

**لا توجد بنية خادمية متاحة لهذا المشروع الآن. لم ننزّل التصدير الكامل، ولم نشغّل استيرادًا كاملًا أو ننشر هذه الخدمة.** لا يتوفر عدد منتجات مستوردة كامل أو إصدار تصدير إنتاجي. تبقى عينة الهاتف الموثّقة (ستة منتجات) والبحث المباشر الحالي في OFF كما هي. هذه العينة ليست بديلًا عن الاستيراد الكامل.

المتاح فعليًا: مستورد متدفق قابل للاستئناف، قاعدة مستقلة مع فهرس FTS5، API قراءة وبحث وتصدير، وربط أصلي اختياري داخل التطبيق. جرى اختبارها محليًا ببيانات اختبارات معلّمة، وبالاستجابات الحقيقية الست المحفوظة في المستودع. لم يُختبر تحميل كتالوج متعدد الملايين أو زمن استيراده أو استهلاكه الكامل للقرص والذاكرة؛ يلزم قياس ذلك على الخادم الفعلي.

## المتطلبات

Python 3.11 أو أحدث، SQLite مع FTS5، مساحة كافية للتصدير المضغوط والبيانات الخام المضغوطة والفهرس وملفات WAL والنسخ الاحتياطية. لا توجد مكتبات Python إضافية. هذه قاعدة **عامة مستقلة**؛ لا تضع مسار قاعدة المستخدم أو يومياته في أمر الاستيراد. يتحقق `application_id` ويرفض قواعد SQLite غير التابعة لهذه الأداة. لا يقرأ المستورد أو الخادم أي بيانات صحية أو شخصية.

## المرجع والتنزيل

تمت مراجعة [توثيق API الرسمي](https://openfoodfacts.github.io/openfoodfacts-server/api/) بتاريخ العمل. يوصي بالتصادير الجماعية للكتالوج الكبير بدل تصفح نتائج API. [توثيق Robotoff الرسمي](https://openfoodfacts.github.io/robotoff/explanations/interactions-product-opener/) يحدد ملف JSONL الكامل:

`https://static.openfoodfacts.org/data/openfoodfacts-products.jsonl.gz`

لا تستخدم ملف العينة random-modulo أو ملف CSV قديم وتصفه بأنه كامل. لا تعتمد على تاريخ HTTP وحده لإثبات حداثة المحتوى؛ راجع تواريخ المنتجات وعدّ السجلات ونسخة المخطط بعد التنزيل. الملف قد يتغير يوميًا، لذلك احفظ نسخة محلية غير قابلة للتغيير وتاريخها وHeaders وبصمتها قبل الاستيراد.

مثال تنزيل **ينفّذه مسؤول الخادم فقط** بعد توفير التخزين:

```sh
curl --fail --location \
  --user-agent 'LuqmaIOS/2.9 (+https://github.com/itssali911-netizen/Loqma-iphone)' \
  --dump-header off-export.headers \
  --output off-YYYY-MM-DD.jsonl.gz \
  'https://static.openfoodfacts.org/data/openfoodfacts-products.jsonl.gz'
sha256sum off-YYYY-MM-DD.jsonl.gz
```

الرابط في User-Agent وسيلة تواصل حقيقية للمشروع، وليس بريدًا مختلقًا. توثيق OFF يطلب تعريف التطبيق ووسيلة تواصل؛ عند تسجيل الاستخدام لديهم يمكن إضافة بريد حقيقي يحدده مالك المشروع. حدود API الموثّقة حاليًا 15 طلب منتج و10 طلبات بحث في الدقيقة لكل IP؛ يحتفظ التطبيق بقيوده الحالية، ولا يستخدم API لجمع الكتالوج.

## الاستيراد والاستئناف والتحديث

```sh
python3 Server/OFFCatalog/catalog.py \
  --input /data/off-YYYY-MM-DD.jsonl.gz \
  --database /data/luqma-off.sqlite \
  --export-id off-YYYY-MM-DD-SHA256PREFIX \
  --export-date YYYY-MM-DD \
  --sha256 ACTUAL_SHA256 \
  --batch-size 250 \
  --finalize > import-report.json
```

استبدل القيم الكبيرة ببيانات الملف الحقيقية. الأمر لا ينزّل شيئًا ولا يستورد عينة ضمنية. يعالج سطرًا واحدًا في الذاكرة، بحد وقائي 64 MiB للسطر؛ لا يقسم السطر الأكبر، بل يوقف الاستيراد ليفحصه المسؤول. يثبّت الصفوف وإحصاءاتها ونقطة الاستئناف في معاملة واحدة لكل دفعة. تكرار الأمر بالملف والمعرّف نفسيهما يستأنف من آخر سطر مثبت ولا يضاعف المنتجات. يقارن SHA-256 وحجم الملف وعنوان المصدر وتاريخ التصدير ويرفض استئناف ملف تغيّر. استئناف gzip يعيد فك البدايات حتى نقطة الاستئناف؛ لا يدّعي قفزًا ثابت الزمن داخل gzip.

المخرجات الفعلية تحتوي `records_read` و`inserted` و`updated` و`unchanged` و`rejected` و`unnamed` و`line_number` و`completed` و`finalized` و`retired` ونسخة التصدير وبصمتها وتوقيتها. يحتفظ جدول `import_rejections` بالسطر الأصلي المضغوط وسبب الرفض ورقمه. لا تُحذف حقول غير معروفة من المصدر: كل صف مقبول محفوظ كاملًا في `raw_zlib` مع بصمته. الباركود نص مع أصفاره البادئة، والمفتاح هو معرّف OFF، لا تشابه الاسم. لا توجد تصفية بلد.

`--finalize` يعلّم المنتجات الغائبة عن التصدير الكامل غير نشطة بعد EOF سليم فقط؛ يحتفظ بسجلاتها الخام. يرفض الإنهاء عند وجود صفوف مرفوضة، ويرفض إنهاء نسخة أقدم بعد بدء نسخة أحدث. يمكن إضافته في إعادة تشغيل ملف اكتمل دون إنهاء بعد التحقق من البصمة. المعالجة لا تمس يوميات الهاتف أو الأطعمة اليدوية أو الوصفات؛ القيم الغذائية التاريخية تبقى snapshots.

للتحديث استخدم تنزيلًا كاملًا مثبتًا جديدًا بمعرّف جديد ثم upsert. لا يفترض هذا الإصدار توفر diff موثوق، ولا يساوي الغياب في دفعة جزئية بحذف منتج. يوفّر OFF أيضًا مشاريع تحديثات أخرى، لكن لم تُعتمد هنا دون مخطط وعقد موثّقين. اختبر التحديث في قاعدة staging منفصلة، ثم انقل الخدمة إلى القاعدة المكتملة بعد فحوص التغطية والتواريخ و`quick_check` وفحص FTS؛ لا تنشر قاعدة نصف مستوردة. يحتفظ المستورد بكل الصفوف الناقصة؛ المنتجات دون اسم أصلي تظل قابلة للتصدير في البيانات الخام ولا تُرسل كـFood باسم مختلق.

## دلالات التغذية

الأساس هو [شرح التغذية الرسمي](https://openfoodfacts.github.io/openfoodfacts-server/dev/explain-nutrition-data/). القيم المفقودة تظل مفقودة؛ الصفر المصرّح به يبقى صفرًا. لا تُحسب kcal من الماكروز. يُحوّل kJ إلى kcal بمعامل 4.184 فقط حين تكون الوحدة معروفة. تُحوّل mg/µg إلى g للوحدات المعلنة. مجموعات التغذية الجديدة تقبل `packaging` أو `manufacturer` و`as_sold` فقط، وتحفظ الأساس `100g` أو `100ml` أو الحصة. لا تخلطها مع `prepared` أو تقدير آلي أو USDA. المخطط غير المعروف محفوظ خامًا، وقيمه غير المفهومة غير مُفبركة.

في المخطط القديم، حقول `*_100g` يمكن أن تعني 100 g أو 100 ml؛ تبقى بيانات الوحدة الصريحة والحصة هي المحدد، دون استنتاج كثافة. لا يُستخدم وزن العبوة كوزن قطعة، ولا تُحوّل كتلة إلى حجم. لا يُنشأ `servingNutrition` إلا عند اكتمال القيم والحصة المتوافقة في الوحدة أو وجود قيم حصة صريحة كاملة. استعراض منتج ناقص لا يسمح بحفظ وجبة بقيم صفرية مصطنعة؛ يظل تحقق `Food.total` الحالي مسؤولًا عن منع الحفظ غير الصالح.

## تشغيل API وربط iOS

```sh
python3 Server/OFFCatalog/server.py \
  --database /data/luqma-off.sqlite --host 127.0.0.1 --port 8781 --allow-export
```

مسارات GET:

- `/v1/products?q=حليب&page=1&page_size=50`: بحث عربي/إنجليزي، terms مع prefix وAND، كل اللغات الموجودة في الأسماء/العلامة تُفهرس. حدود الصفحة 1–100، وترتيب ثابت بمعرّف المصدر. لا يُستدعى OFF لكل ضغطة. لا يدعي هذا الفهرس فهمًا دلاليًا أو ترجمة للأسماء.
- `/v1/products/CODE`: المنتج المحدد بنفس الهوية.
- `/v1/status`: آخر ثلاث عمليات استيراد وإحصاءاتها الفعلية؛ ليست ادعاءً بأن التصدير كامل إن كان `completed=0`.
- `/v1/licence`: النسبة والتراخيص ورابط تصدير القاعدة المشتقة إن فُعّل.
- `/v1/export`: اختياري، JSONL gzip متدفق يحتوي كل السجلات العامة النشطة، المصدر الخام وFood المطبع والنسخة والترخيص. لا يتضمن بيانات المستخدم أو قاعدة MFP.

الخادم أداة تشغيل أصلية خلف reverse proxy؛ لا تعرّض Python HTTP مباشرة للإنترنت. يلزم HTTPS وشهادة حقيقية ومشرف خدمة وحدود اتصال ومعدل ووقت وذاكرة ومراقبة مساحة ونسخ احتياطية، مع سياسة منفصلة لعرض نطاق تصدير القاعدة الكبيرة. الاستعلامات مقيدة بمهلة CPU وبحدود اتصالات/threads، وتستخدم معاملات SQL مربوطة، ولا تُسجل نصوص البحث. لا توجد مفاتيح إدارية أو واجهات كتابة في هذه الخدمة.

بعد استيراد كامل موثّق ونشر API فعلي وقياسه، يضيف مسؤول البناء قيمة Info.plist النصية `LUQMAFoodCatalogBaseURL` بعنوان HTTPS الأساسي. **لم تُضف قيمة وهمية للمشروع**. `FoodDatabase` يختار هذا الفهرس عند وجود عنوان صالح؛ بدونه يعمل البحث المباشر السابق. لا يبدّل بصمت إلى نتائج مصدر آخر عند تعطل الخادم. منتج باركود غير موجود فعليًا في النسخة المحلية يمكن طلبه من OFF الحالي بالمسار القديم. تفاصيل المنتج تُحلّ قبل التسجيل؛ لا تتغير هوية المصدر أو محفوظات المستخدم. إلغاء الطلبات ورمز حداثة الاستعلام الموجودان في FoodAddView يمنعان استبدال بحث أحدث بنتيجة متأخرة.

## التراخيص والنسبة

[دليل OFF الرسمي](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorials/license-be-on-the-legal-side/) يحدد ODbL 1.0 للقاعدة وDbCL 1.0 للمحتويات و[CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/) للصور. لا تضف صور OFF للواجهة دون نسبة الصورة وشروط إعادة استخدامها. هذا التنفيذ يحتفظ بروابط صور المصدر وبياناتها داخليًا، ولا يضيف عرض صور جديدًا.

إخفاء المصدر من بطاقة بحث لا يزيل التزام النسبة. التطبيق يعرض معلومات المصدر والترخيص في موضع بيانات المنتجات القريب من النتائج وتفاصيل منتج OFF؛ يلزم إتاحة نسخة القاعدة المشتقة المستخدمة للناس تحت ODbL قبل إطلاق خدمة الكتالوج العام، عبر `/v1/export` أو تنزيل مُدار مكافئ مع الرخصة. لا يُخلط كتالوج OFF في قاعدة MFP ذات حقوق غير مثبتة أو في قاعدة مستخدم خاصة. تمت مراجعة [نص ODbL](https://opendatacommons.org/licenses/odbl/1-0/) وDbCL؛ كانت صفحات OFF wiki والشروط محجوبة آليًا في البيئة، لذا هذا التوثيق ليس شهادة امتثال قانوني شاملة ولا بديلًا عن مراجعة الالتزامات بحسب الاستخدام الفعلي.

## الفحوص المنفذة والحدود

```sh
python3 -B -m unittest BuildTests.test_off_catalog_server BuildTests.test_food_catalog -v
```

اختبارات المستورد والخادم تستخدم ملفات مؤقتة: استئناف/تكرار/upsert، هوية نصية وأصفار بادئة، رفض hash خاطئ أو ملف متغير، عدم لمس قاعدة شخصية، EOF/retirement، الأسماء العربية/الإنجليزية وpagination، مغذيات ناقصة وصفر حقيقي ووحدات/حصص، عدم تصفية بلد، حفظ المصدر الخام، سلامة FTS، ومسارات HTTP وتصدير gzip حقيقي. اختبار إضافي يعبر عبر الاستجابات الست الحقيقية المحفوظة؛ ليس استيرادًا كاملًا. اختبارات Swift في `FoodCatalogConfigurationTests.swift` تتحقق من عقد الربط، الهوية، الحصص، التخزين القديم وثبات اليوميات؛ تشغيلها يتطلب Swift/Xcode وتُسجل نتيجته من CI منفصلة.

غير متحقق: كامل الكتالوج، الاستيراد الإنتاجي والفهرسة على حجم حقيقي، API مستضاف، ضغط متزامن واسع، مساحة/ذاكرة/زمن الإنتاج، وقراءات API من تطبيق iPhone إلى خادم كامل. لا توجد إحصاءات أو وعود أداء مختلقة لهذه الأجزاء.
