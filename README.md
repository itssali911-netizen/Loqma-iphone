# Luqma Native iOS — version 1.6

88 Swift tests, 26 Python tests, iPhoneOS Release build, independent IPA verification and four actual SwiftUI Simulator screenshots passed. The unchanged optional local model was not revalidated for this release; its earlier build31 fixture failure is retained separately. The workflow was deliberately stopped after the native app and four screenshots passed. Gemini is the default and passed a separate real API test on a public meal and a blank control. Physical iPhone, personal Apple signing and Health authorization remain to be verified on the device. [البناء / Build](https://github.com/itssali911-netizen/Loqma-iphone/actions/runs/38278925435)

Version 1.6 adds all 744 regional food records from the user's supplied MyFitnessPal 26.33.0 IPA, alongside six Open Food Facts starter products and live OFF search. It adds local query completions and Search all actions, exact Gemini 3.8 Flash cloud recognition, a charcoal/orange PowerPeak-style SwiftUI interface, and a new meal/bite logo. Native compilation and all four real Simulator screenshots are verified; see VALIDATION.md for evidence and limits.

The 744-record package seed is not MyFitnessPal's complete global database. It retains 3,830 source portion choices; 713 foods and 3,736 choices have complete accepted nutrition. All 31 incomplete foods remain searchable, without fabricated zero values. A source multiplier defines each declared serving, with no assumed per-100g basis or liquid density. Choices and explicit corrections persist through backups. [Artifact evidence](MFP-IPA-EVIDENCE-AR.md) distinguishes static facts, inferences and unknown server ranking.

Search considers every normalized query word across names, aliases and brands, without truncating local matches. Exact/prefix matches are promoted as Best match. Suggestions are local search actions, never automatic diary additions; online queries are explicitly submitted under OFF's published rate limits and pagination window. Recent/Frequent use logged entries. Sources remain attributed separately.

Gemini uses the exact `gemini-3.8-flash` REST model, photo input and bounded structured JSON. The selected photo and optional description go to Google; diary and Health data are not sent. Responses provide component names and rough weights only. The user chooses actual catalog food and serving before logging. On-device models remain optional and never silently replace Gemini.

A real API check succeeded for a pinned public-domain meal and a blank control; both returned HTTP200 with valid structured outputs. This is not a physical-iPhone run or measured portion-accuracy result. Key format and responseFormat enum defects found by this test were fixed. [Setup and data policy](GEMINI-SETUP-AR.md).

Personal credentials are stored in iOS Keychain and excluded from backups, source and IPA resources. A private setup JSON can be imported from Settings → Meal analysis; it is not a public deliverable or part of this repository. Never commit an actual API key. API usage follows the user's Google account quotas and pricing.

The four primary destinations are Today, Kitchen, Progress and Settings, with a central Add action. Arabic RTL and English remain supported. Per-meal additions initialize the meal picker without overriding later user choices. Brand images are embedded, including an opaque1024px iOS icon.

Build with Xcode26.3+, iPhone/iOS17+ through Scripts/build_ios.py. Core tests are a standalone Swift package. Scripts/ui_preview.py captures actual SwiftUI screens on a newly created disposable Simulator. The sideload IPA needs personal Apple signing; preserve the installed identifier `app.luqma.diary.2AV9NV468K` and same account after a backup. [Health setup](HEALTH-SETUP-AR.md). Current/historical verification is in [VALIDATION.md](VALIDATION.md).
